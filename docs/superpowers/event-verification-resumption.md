## What Is the Event Verification Mechanism

The verification script (`verify_trace_events.py`) reads two inputs:
1. **simulation_events.csv** — events emitted during simulation (frontend price interactions table data)
2. **simulation_trace.log** — structured per-bar trace log with OHLC, line evaluations, and [STATE] blocks

It produces a **clean accuracy/completeness report** answering:
- **Accuracy**: Were events that fired correctly identified per EVENT_TYPES.md definitions?
- **Completeness**: Were any events missed on bars where the state machine evaluated lines?

The verification also exports ML training data (`events_ml.csv`, `bars_ml.csv`).

## Bugs Found and Fixed in Verification Script

Three bugs were fixed in `verify_trace_events.py`:

1. **`_parse_eval_line` wrong bracket** — was taking first bracket `[Bar N]` instead of the one with `@` (the line eval bracket). Fixed to use `re.findall()` and pick the one containing `@`.

2. **`_parse_eval_line` fan name mismatch** — parsed `H1-L1` from trace lines but state blocks use `Fan_H1_L1`. Fixed with normalization step.

3. **`_normalize_fan` hyphen handling** — `P1 (L2-H1)` was becoming `Fan_L2-H1` instead of `Fan_L2_H1`. Fixed with `.replace('-', '_')`.

## Outstanding Issues

### 1. Real State Machine Bugs (Not Verification Script Bugs)

The verification is **working correctly** — it's exposing real bugs in the state machine:

**BREACH_CONFIRMED (all 312 inaccurate):** State machine uses `>=` or `<=` (non-strict inequality) but EVENT_TYPES.md requires strict `>` or `<`. Example: close=24217.65, boundary=24232.40, direction=UP → close is NOT > boundary, so BREACH_CONFIRMED should not have fired.

**TOUCH (all 78 inaccurate):** State machine emits TOUCH when close ≠ line_price. Our reclassification requires C == line_price for SUPPORT_TOUCH / RESISTANCE_TOUCH. Example: line=24177.94, close=24195.50 → C ≠ L, so not a valid TOUCH.

**CROSS_DOWN (20 inaccurate):** Gap crosses — open was already through the line, can't be CROSS_DOWN per EVENT_TYPES.md definition.

### 2. Completeness Shows Negative

`bars_evaluated` (417 from trace) < `missed_count` (1058) — the miss detection logic is comparing across mismatched bar indices. The timestamp-based bar lookup works for accuracy but creates duplicate detections for completeness.

### 3. BREACH_CONFIRMED_NO_ALPHA State Blocks Missing

Some events show "STATE block missing" in the report (bars 481, 1262 in the last run). These events should have [STATE] blocks from the trace log but the state machine may not be emitting them for this event type.
